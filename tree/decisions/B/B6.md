## Decision

Wherever upstream keeps a plain object keyed by name (a node's inputs, outputs and controls, a node's data and fetched inputs), Ruggine uses a map that iterates in JavaScript's own property order: canonical array-index keys in ascending numeric order first, then the other keys in insertion order. Re-adding a removed key puts it at the end.

## Why

The engine's default inputs and outputs come from that key order, and so does anything Solenoid lists or saves from it, so a different order would be a different answer.
